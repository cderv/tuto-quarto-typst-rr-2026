_quarto.yml — centraliser la config

Un projet Quarto = un dossier avec _quarto.yml.

_quarto.yml
project:
  type: default

format: typst
  • Tous les .qmd du projet produisent un PDF via Typst automatiquement
  • Votre _brand.yml à la racine s’applique à tout le projet
  • Finie la répétition de YAML dans chaque fichier !

Transition naturelle : au Bloc 1 on a stylé un document unique. Maintenant on passe à l’échelle. Le _brand.yml créé dans l’exercice 1 va être réutilisé ici — on le déplace juste à la racine.

type: book

_quarto.yml
project:
  type: book

book:
  title: "Anatomie d'une saga"
  author: "Mon Mothma"
  chapters:
    - index.qmd
    - 01-anatomie.qmd
    - 02-origines.qmd
    - conclusion.qmd
  appendices:
    - annexe-donnees.qmd

format: typst

Depuis Quarto 1.9, format: typst sur un book active automatiquement orange-book:

  • Page de couverture générée automatiquement
  • Numérotation par chapitre (Figure 2.1, Table 2.1…)
  • En-têtes et pieds de page stylisés
  • Intégration _brand.yml pour les couleurs et le logo

Le moment wow : zéro configuration supplémentaire. On montre le _quarto.yml, on rend, et on obtient un livre pro. Orange-book est une extension bundlée dans Quarto 1.9.

Découpage du YAML en 4 fragments via code-line-numbers pour étaler le récit : (1) project.type: book = on déclare un projet livre ; (2) bloc book: avec titre/auteur/chapters = configuration minimale ; (3) appendices: = ce qui sort du flux principal et devient « Annexe A » ; (4) format: typst = inchangé depuis l’étape 1, c’est type: book qui active orange-book. 4 beats = 4 idées, plus digestible que tout d’un coup.

Construisons un livre ensemble

Faisons ensemble !

  1. Créer _quarto.yml avec project: { type: default } + format: typst → 5 PDF séparés
  2. Passer à type: book (le format: typst reste, orange-book s’active automatiquement) → PDF unique avec couverture et TOC
  3. Copier _brand.yml (+ _logo-sw.svg) à la racine → couverture jaune SW, Orbitron, Inter

Démo live, 3 étapes en ~10 min. à l’étape 2 le PDF unique avec couverture orange-book apparaît. Étape 3 = confirmation visuelle (la charte de Bloc 1 ressuscite côté book).

Montrer pendant la démo : la numérotation automatique Figure 1.1 / Figure 2.1 / Table 1.1 / Table 2.1 (en français Quarto rend « Figure » et « Table » — pas « Fig » / « Tab »), l’apparition du logo SVG sur la couverture, le passage des tableaux gt en Inter (Étape 3).

Mentionner les bonus rapidement à la fin de la démo : références croisées @fig-anatomie-mass / @sec-origines et .content-visible when-format="typst" + pagebreak. Pas obligés de les démontrer ici — c’est le contenu des bonus B1/B2 du Your turn.

Si vous voyez des chiffres mal espacés (« 1 7 5 » au lieu de « 175 ») dans les tableaux à l’étape 3 chez un participant Windows/macOS : c’est normal, bug gt → Typst sur fallback de fonts. Le workaround opt_table_font(font = "Inter") est appliqué dans la correction (mais pas dans le starter — bug volontairement visible). Pas la peine de s’attarder, mentionner et passer.

Problèmes fréquents : mauvais chemin vers les chapitres, oubli du tiret devant les noms de fichiers dans chapters:, oubli de l’underscore dans _quarto.yml ou _brand.yml.

Exercice 2

À vous !

3 étapes principales (12 min, attendues de tous) :

  1. _quarto.yml avec type: default + format: typst → 5 PDF
  2. Passer à type: book (format inchangé) → PDF unique
  3. _brand.yml (+ _logo-sw.svg) à la racine → charte jaune SW

2 bonus (3 min, pour les rapides) :

  • B1. Références croisées @fig-anatomie-mass + @sec-origines dans conclusion.qmd
  • B2. .content-visible when-format="typst" + {{< pagebreak >}}

Pas de _brand.yml ? Copiez _brand-fallback.yml (à renommer) et correction/_logo-sw.svg à la racine. Voir la page Exercice 2.

15 minutes total : 12 min sur les 3 core + 3 min de bonus pour les rapides. Annoncer clairement que les bonus sont pour ceux qui ont fini, pas pour tout le monde

Le fallback _brand-fallback.yml (+ correction/_logo-sw.svg) est important : ceux qui n’ont pas fini Bloc 1 peuvent les copier. Passer dans les rangs, repérer ceux qui peinent à l’étape 1 — souvent un underscore manquant.

Pour ceux qui finissent vite : pousser le bonus B1 (références croisées) en premier — c’est le plus visuel et ça utilise les labels qui sont déjà dans le starter (tbl-anatomie-mass, fig-anatomie-mass, #sec-origines). Le bonus B2 (pagebreak) demande de connaître la syntaxe .content-visible — l’avoir montrée à la fin de Our turn aide.

Saviez-vous que…

Pépites pour aller plus loin

  • Template partials — Le fichier typst-show.typ (et son typst-template.typ côté template par défaut) contrôle la génération du .typ. Vous pouvez le remplacer pour personnaliser header, footer, page de titre… Suffit souvent de toucher typst-show.typ seul.
  • Créer un format partageable — quarto create extension format:typst génère un squelette d’extension prêt à publier sur GitHub
  • Formats communautaires — AMS, IEEE, poster, lettre, CV… sur quarto-ext/typst-templates

Plus de détails sur la page Ressources

Slide rapide, 2-3 minutes max. Template partials = le concept le plus avancé du workshop, mais on ne fait que le mentionner ici. Les gens motivés iront creuser.

Fusible à couper si le timing serre — sauter directement au wrap-up qui suit (3 slides obligatoires, ne pas sauter).

Ce que vous savez faire maintenant

  • Produire un PDF pro avec format: typst, sans LaTeX
  • Inspecter le pipeline .qmd → .typ → .pdf via keep-typ: true
  • Personnaliser couleurs, polices et logo via _brand.yml
  • Assembler plusieurs .qmd en livre avec type: book
  • Savoir où chercher pour aller plus loin (partials, formats communautaires — pistes pour après le tutoriel, pas couverts en séance)
