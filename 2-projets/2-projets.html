_quarto.yml — tout régler au même endroit

Un projet Quarto = un dossier avec _quarto.yml.

_quarto.yml
project:
  type: default

format: typst
mon-projet/
├── _quarto.yml   ← config projet
├── _brand.yml    ← charte
├── index.qmd
├── 01-anatomie.qmd
├── 02-origines.qmd
└── conclusion.qmd
  • Tous les .qmd du projet produisent un PDF via Typst automatiquement
  • Votre _brand.yml à la racine s’applique à tout le projet
  • Plus besoin de répéter le YAML dans chaque fichier !

Transition naturelle : au Bloc 1 on a stylé un document unique. Maintenant on passe à l’échelle. Le _brand.yml créé dans l’exercice 1 va être réutilisé ici — on le déplace juste à la racine.

type: book

_quarto.yml
project:
  type: book

book:
  title: "Anatomie d'une saga"
  author: "Mon Mothma"
  chapters:
    - index.qmd
    - 01-anatomie.qmd
    - 02-origines.qmd
    - conclusion.qmd
  appendices:
    - annexe-donnees.qmd

format: typst

Depuis Quarto 1.9, format: typst sur un project.type: book active orange-book :

Le moment wow : zéro configuration supplémentaire. On montre le _quarto.yml, on rend, et on obtient un livre pro. Orange-book est une extension bundlée dans Quarto 1.9.

Pont avec le Bloc 1 (si on le demande) : au Bloc 1, pour des titres rouges il fallait écrire typography.headings.color: primary à la main (template article = Quarto ne colore que les liens). Ici, orange-book reprend primary comme couleur d’accent (main-color) et colore titres + couverture + TOC toute seule — c’est ça, la valeur d’une extension. Orange-book ne lit d’ailleurs pas headings.color : cette clé est donc sans effet en mode book. Et si on demande « comment changer la couleur des titres ici ? » : c’est color.primary (= main-color) qu’on modifie — mais ça recolore tout l’accent d’un coup (couverture, TOC, numéros de chapitre, liens), on ne dissocie pas la couleur des titres du reste. Bloc 1 = contrôle fin clé par clé ; Bloc 2 = un seul levier (primary), c’est le prix de l’opinionated. À ressortir seulement si la question vient.

Découpage du YAML en 4 fragments via code-line-numbers pour étaler le récit : (1) project.type: book = on déclare un projet livre ; (2) bloc book: avec titre/auteur/chapters = configuration minimale ; (3) appendices: = ce qui sort du flux principal et devient « Annexe A » ; (4) format: typst = inchangé depuis l’étape 1, c’est type: book qui active orange-book. 4 beats = 4 idées, plus digestible que tout d’un coup.

Construisons un livre ensemble

Faisons ensemble !

On part du dossier starter/, on y crée un _quarto.yml, puis on le bascule en livre.

1. type: default → render → 5 PDF séparés

_quarto.yml
project:
  type: default

format: typst

2. type: book → render → PDF unique (couverture + TOC)

_quarto.yml
project:
  type: book

book:
  title: "Anatomie d'une saga"
  author: "Mon Mothma"
  chapters:
    - index.qmd
    - 01-anatomie.qmd
    - 02-origines.qmd
    - conclusion.qmd

format: typst

Rendre le projet : quarto render à la racine du dossier (ou bouton Render) — Quarto rend tout le projet. → Ensuite, à vous : appendices, _brand.yml au niveau projet, bonus.

Démo live ultra-courte : 5-6 min. Le pas-à-pas détaillé (snippets à coller, ressources, pièges, transition Your turn) est dans le doc animateur dédié _speaker/demo-bloc2-our-turn.qmd — pas de duplication ici (les snippets sont déjà sur la slide).

Pourquoi minimal : Our turn montre comment _quarto.yml + type: book produit un livre PDF unique. appendices, copie de _brand.yml et bonus restent dans Your turn — éviter la redondance Bloc 1.

Effet visuel à l’étape 2 : on passe de 5 PDF séparés à 1 PDF unique avec couverture + TOC + numérotation auto (Figure 1.1, Table 2.1…) sans rien d’autre que type: book. C’est orange-book qui s’active sur format: typst + type: book.

Saviez-vous que…

Saviez-vous que…

  • Template partials — Le fichier typst-show.typ (et son typst-template.typ côté template par défaut) contrôle la génération du .typ. Vous pouvez le remplacer pour personnaliser header, footer, page de titre… Suffit souvent de toucher typst-show.typ seul.
  • Créer un format partageable — quarto create extension format:typst génère un squelette d’extension prêt à publier sur GitHub
  • Formats communautaires — AMS, IEEE, poster, lettre, CV… sur quarto-ext/typst-templates

Ce que vous savez faire maintenant

  • Produire un PDF pro avec format: typst, sans LaTeX
  • Voir ce qui se passe entre le .qmd et le .pdf, avec keep-typ: true
  • Personnaliser couleurs, polices (Google ou locales source: file) et logo via _brand.yml
  • Assembler plusieurs .qmd en livre avec type: book
  • Savoir où chercher pour aller plus loin (partials, formats communautaires — pistes pour après le tutoriel, pas couverts en séance)
