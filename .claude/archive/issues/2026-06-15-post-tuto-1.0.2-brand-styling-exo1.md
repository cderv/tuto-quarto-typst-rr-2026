## Le problème de fond (rappel)

La correction de l'exo 1 (`exercises/01-document-typst/correction/rapport-starwars.qmd`)
embarque **tout le « Bonus B4 » de l'exo 2** (câblage R `brand.yml` : `styliser_brand()`,

qui ouvre une 3e voie d'accès à la charte) **sans qu'aucune des 4 étapes ne le demande
ni ne l'annonce**. Un·e débutant·e qui ouvre cette correction comme filet de secours
tombe sur ~40 lignes de R jamais enseignées → faux sentiment d'échec, B4 spoilé.

Racine : la dichotomie **auto** (`_brand.yml` lu par Quarto/Typst → mise en page :
liens, fond, polices, titres) **vs câblé-main** (sorties R `gt`/`ggplot` → à brancher
soi-même en R via le paquet `brand.yml`) n'est nommée nulle part en Bloc 1.

L'exo 2, lui, est exemplaire (B4 balisé bonus optionnel, étape 3 prévient « tableaux
restent bruts », corrections étiquetées `# --- Bonus B4 (optionnel) appliqué ---`).

## Correctifs polices Typst (book + Star Jedi) — 1.0.2

Deux soucis distincts trouvés le 2026-06-15 en re-rendant le book de l'exo 2. Les deux
touchent `exercises/**/correction/` (fichiers gelés du paquet 1.0.1) → 1.0.2.
**Les deux fixes se combinent dans le même `include-in-header`.** Re-vérifier sur le book
complet (avec R) avant de livrer.

### A. Corps du book en **serif** au lieu d'Inter (bug Quarto, pas notre config)

Détail + repro : `.claude/archive/issues/2026-06-15-quarto-book-typst-base-font.md`.
En mode `book`, Quarto ne passe pas `typography.base` / `mainfont` au template
orange-book (`book.with(...)` sans argument `font:`) → le corps tombe en Libertinus
serif. Titres (Star Jedi) OK. Vérifié sur Quarto **1.10.11** ET 1.9.36. Notre `_brand.yml`
est correct (Inter s'applique bien en **doc simple** — exo 1 OK). **Workaround vérifié** :

```yaml
# exercises/02-projet-book/correction/_quarto.yml → format.typst
include-in-header:
  - text: |
      #set text(font: "Inter")
```

### B. Lisibilité **Star Jedi** : capitales déformées (la fonte, pas un bug)

Fonte Star Jedi (<https://www.dafont.com/star-jedi.font>) : les emplacements
**MAJUSCULES** portent des glyphes décoratifs « logo » (**I→H, O→N, Q→M, U→K**…), les
**minuscules** donnent des capitales propres. Donc une initiale I/O/Q/U dans un titre
sort déformée. Touche **3 titres** : « Qui… » → Mui (sous-titre exo 1), « Introduction »
→ Hntroduction (section exo 1), « Origines » → Nrigines (chapitre exo 2). Tout le reste
est net.

**Fix vérifié** (titres de section / chapitres) — lowercase les capitales **dans les
titres**, préserve numérotation + couleur + style orange-book :

```typst
// dans include-in-header (Typst)
#show heading: it => {
  show regex("\p{Lu}"): c => lower(c.text)
  it
}
```

**Limite** : ce show-rule corrige les éléments `heading` (sections, chapitres), **pas**
le **sous-titre de document** « Qui… » (paramètre template, pas un heading). Pour
celui-ci : soit reformuler le sous-titre (éviter l'initiale Q/I/O/U), soit le lowercaser
à la source. Idem côté charte si on veut « THE SAGA AWAKENS » impeccable.

**Portée des fichiers à toucher** : `exercises/01-document-typst/correction/` (titres exo
1), `exercises/02-projet-book/correction/` (book : A + B), éventuellement `_charte/` et
les `_fonts/`/starters. Tout gelé → 1.0.2.
